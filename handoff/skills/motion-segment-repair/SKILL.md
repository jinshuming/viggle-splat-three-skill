# 动作某一段的修复

只改目标肢体、目标帧段，其余保持原样。改的是 GLB 里的**局部旋转轨道**（int16 归一化四元数，原地写回，文件大小不变）。
骨骼名称、朝向、25 fps 等约定见 `../viggle-motion-edit/SKILL.md` 与其 `references/`。本 skill 补充**检查与目标确认的 UI 流程**和**修复方法**。

## 1. 先在 UI 里检查，不要凭想象改

1. 用 `assets/viewer-template/`（three.js + `@viggle/splat-engine-three`，见下）跑一个本地 viewer。必备功能：
   - **底部时间轴**：拖动即暂停并跳转，松手恢复；松手前是暂停的就保持暂停。
   - **帧号显示**：`帧 N / 总帧数`。帧率取自 GLB 关键帧（`(count-1)/max(time)`，舞蹈为 25 fps），**不要**默认 30。
   - 双角色并排、可切换角色对；有参考视频时按"视频时间 = 动作时间 + 偏移"同步。
2. 让用户在 viewer 里拖到有问题的帧，**截图并标注目标**：
   - 在截图上用箭头标出手/肢体"应该去的方向"，或用文字说明（"第 112 帧之前自然下垂""远离身体"）。
   - 记下：**第几帧**（时间轴显示的帧号）、**哪个角色/哪只手**、**目标方向**、**从哪一帧起恢复原动作**。
   - 用户说"右手"时先和画面对一下：角色正对镜头时，角色的右手在**画面左侧**。拿不准就问一句。
3. 复述一遍你的理解（帧段、肢体、方向）再动手。截图是目标示意，不是精确角度；量级由你估，之后让用户看效果再调。

## 2. 先量数据，再改

```bash
python3 ../viggle-motion-edit/scripts/inspect_motion.py clip.glb      # 结构检查，改前改后各跑一次
```
读 GLB 时注意（`scripts/glblib.py` 已处理）：
- 旋转访问器是 `componentType 5122`（int16 归一化），不是 float。按 float 读会得到 NaN/乱码。
- `root` 的旋转轨道含 NaN，运行时会被钳到 bind；做正向运动学时跳过它。
- 每个骨骼有一条 translation（常量骨长）和一条 rotation 轨道。动画值是**绝对局部旋转**，不是相对 bind 的增量。

## 3. 标定方向（关键，跳过会返工）

**不要相信自己按文档坐标系算出来的世界方向。** 本任务里按 FK 算"向外 17°"，在 viewer 里手却跑到肚子前面；按 UE 轴向换算也不对。根因是 viewer 的坐标/朝向和直觉不一致。正确做法是**用 viewer 实测**：

```bash
python3 scripts/axis_probe.py clip.glb --side r --out probe.glb
```
把 `probe.glb` 放进 viewer，看第 20–35 / 35–50 / 50–65 / 65–80 帧该手臂的样子，判断哪根局部轴、哪个符号能在**画面平面内**把手臂放低。本包实测：上臂局部 **X 轴负方向**放低手臂（`--axis x --axis-sign -1`）；`+X` 抬过头，`±Y` 前后摆（朝向/背离镜头）。左右臂可能相反，换边必须重新标定。
同时目测 bind 姿态手臂高出水平多少度，填 `--beta`（本包约 25°，由 T-pose 帧估计：把上臂/前臂/手全设为 bind 就是 T-pose）。

## 4. 修复

```bash
python3 scripts/repair_arm.py clip.glb --side r --end 112 --abduct 25 \
    --swing-frame 52 --swing-extra 19 --swing-width 18
```
- `--end N`：第 N 帧恢复为原动作；`--blend` 帧（默认 20，smoothstep）从修复姿态过渡回去，保证 N 处无跳变。
- `--abduct`：下垂时手臂离竖直方向的角度。**贴身不自然时加大**；猫/宽身角色轮廓宽，要更大才会离开躯干。
- `--elbow`：残余肘弯；肘轴取自原动作第 0 帧前臂旋转的轴，只缩小角度。
- `--swing-frame/-extra/-width`：在某帧摆向更外侧再缓回（余弦钟形，进出平滑）。
- 前臂、手、手指（放松为"bind 与原均值之间"）同步处理；不动锁骨、脊柱、其他骨骼。
- 首次运行把原文件复制到 `_backup/<name>.orig.glb`；之后每次都从备份重算，可反复调参不叠加。
- 其它肢体（腿、头、另一侧）参考 `repair_arm.py` 改骨骼名与标定轴，流程相同。

## 5. 验证（必须在 viewer 里看）

1. `inspect_motion.py` 通过（441 骨、帧数、fps 不变）。
2. 逐一看：修复段内的典型帧、目标帧（如第 52 帧）、过渡段中点、`--end` 帧及之后一帧；对照用户截图的箭头。
3. 刷新后若角色脸或身体短暂"糊掉"，是 splat 刚加载，等 2 秒再截图，不是动作问题。
4. 检查**同一条动作被多个角色使用**（如四对角色的右边那位）：宽/窄身角色下垂是否都不穿模，必要时折中调 `--abduct`。
5. 交付时说明：改了哪个文件、哪一帧段、关键数值、原文件备份位置，以及哪些帧没逐帧看过。

## viewer 模板

`assets/viewer-template/` 是本次用的最小 viewer（Vite + three + 引擎 tgz）：`index.html`（时间轴、帧号、参考视频同步）、`main.js`。使用前：把 `package.json` 里引擎依赖改成本机 `engine/*.tgz` 路径，`npm install && npm run dev`；把 `index.json` 换成自己的角色/动作清单（格式见模板里 `main.js` 的读取处）。角色 `FACE = 0` 时正对 +Z 的相机；`groundLockY = 0`、`rootMotion = 'off'` 让舞蹈原地播放。
